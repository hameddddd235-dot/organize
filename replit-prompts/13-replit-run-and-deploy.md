# البرومبت 13 من 13: التشغيل والنشر على Replit والتحقق

المشروع جاهز، وهو نسخة مطابقة للأصل. نفّذ التعديلات التالية فقط لأن بيئة Replit تحتاجها، ولا تغيّر الواجهة أو المنطق أو النصوص.

## 1. وضع التطوير
- عدّل vite.config.ts ليستمع على 0.0.0.0 والمنفذ 5000 مع allowedHosts: true في server وpreview، مع إبقاء proxy المسار /api إلى http://127.0.0.1:8787.
- اجعل زر Run ينفّذ npm run dev، ووجّه منفذ المعاينة 5000 إلى المنفذ الخارجي 80.

## 2. السماح بأصل Replit
الخادم يرفض أي Origin غير مسموح، لذلك ستفشل طلبات Gemini من رابط Replit إذا لم يُضَف الأصل.
في server/start.cjs كوّن allowedOrigins من:
- قيم APP_ORIGINS إن وجدت، وإلا الأصول الافتراضية الأربعة الموجودة في .env.example.
- https://${REPLIT_DEV_DOMAIN} إذا كان المتغير موجوداً.
- كل نطاق في REPLIT_DOMAINS بعد إضافة https:// إليه.
يجب أن تحتوي القائمة الأصول المحلية دائماً، ولا تعطّل فحص Origin ولا تستخدم *.
تحقق أن النطاقات تصل فعلاً إلى النسخة المنشورة بتجربة التحليل من رابطها العام. أي نطاق خاص يُضاف عبر APP_ORIGINS.

## 3. وضع الإنتاج
- أضف إلى createAnalysisServer خياراً اختيارياً اسمه staticDir. عند وجوده، تُخدم طلبات GET خارج /api من هذا المجلد مع fallback إلى index.html، ويُمنع الخروج من المجلد بأي مسار مثل ../.
- عند عدم تمرير staticDir يبقى سلوك الخادم كما هو تماماً.
- في server/start.cjs: عند NODE_ENV=production مرّر staticDir يشير إلى dist، واستمع على 0.0.0.0 والمنفذ process.env.PORT أو 5000. في التطوير يبقى الاستماع على 127.0.0.1 والمنفذ API_PORT أو 8787.
- انقل jiti من devDependencies إلى dependencies لأن الخادم يحتاجه أثناء التشغيل.
- اضبط إعدادات النشر: البناء npm run build، والتشغيل NODE_ENV=production node server/start.cjs.
- لا تغيّر حد الطلبات ولا تعتمد على X-Forwarded-For.

## 4. مفتاح Gemini
- اقرأ GEMINI_API_KEY وGEMINI_MODEL من Replit Secrets فقط، ولا تكتبهما في أي ملف.
- لا تضع المفتاح في متغير يبدأ بـ VITE_.
- إذا لم يكن المفتاح مضبوطاً، فاطلبه مني عبر واجهة Secrets. يبقى المحلل المحلي عاملاً بدونه.
